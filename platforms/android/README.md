# Android: тестовая версия и подготовка RuStore

Исходный код Android-контейнера находится в `android/`. Все шесть занятий включены, покупки, рекламные SDK и аналитика не подключены. Это тестирование отдельного приложения, а не разрешение монетизации детской аудитории.

## Сборка

Требуются Node.js 22+, JDK 21, Android SDK Platform 36 и Build Tools 35/36. В Android Studio можно установить SDK и открыть каталог `android/`. Внешние инструменты Android, установленные в среде подготовки, лежат в `/tmp` и не включаются в Git.

```sh
npm ci
npm run sync:android
cd android
./gradlew assembleDebug lintDebug
```

Настройте `JAVA_HOME`, `ANDROID_HOME` и при необходимости `android/local.properties` для своей машины. Для экспорта файла и контрольной суммы: `npm run export:android`. На Windows после `npm run sync:android` используйте `android\gradlew.bat -p android assembleDebug lintDebug`.

Пакет тестовой сборки — `ru.nevedomskiy.lapki.test`, версия `0.1.1-test`, versionCode 2. Будущий релиз будет использовать `ru.nevedomskiy.lapki`; это отдельная установка и отдельное хранилище прогресса. RuStore ID 2063773439 не является package name. ID приложения VK Рекламной сети также не является package name.

Тестовый APK подписан отладочным сертификатом. Не загружать его на модерацию магазина. Для выпуска необходимы выбор схемы подписи RuStore, подписанный файл, карточка и возрастная анкета. Неподписанные release-кандидаты 1.0.0 и материалы карточки подготавливаются по [плану выпуска](../../docs/RUSTORE-RELEASE.md). Ключ выпуска и пароли не созданы и не публикуются в Git.

## Что реализовано

- Локальные файлы игры в APK, без CDN, SDK VK/Яндекс, покупок и рекламных запросов. В манифесте нет `INTERNET`, микрофона, контактов, файловых разрешений и рекламного ID. Служебное разрешение AndroidX на собственные внутренние receivers не является доступом к данным пользователя.
- Android 7.0+ (API 24), актуальный Android System WebView/Chrome не ниже 89. Весь пользовательский интерфейс на русском; смена языка устройства его не переводит.
- Системная кнопка «Назад» закрывает диалог, затем возвращает из занятия на главный экран; с главного экрана сворачивает приложение стандартным методом Capacitor App.
- Сворачивание останавливает озвучку и игровую обратную связь. Прогресс сохраняется в локальном хранилище WebView; резервное копирование приложением выключено. Облачной синхронизации нет.
- Родительская справка говорит о хранении на устройстве. Прогресс этого тестового приложения не переносится автоматически в будущую релизную установку.
- Озвучка через собственный небольшой плагин Android TextToSpeech. Выбирается установленный русский голос, которому не требуется сеть. Если его нет, игра остаётся доступной и выводит подсказку; звук не записан в APK. Наличие и качество голоса требуют проверки на реальном устройстве. Установка голосов не запускается автоматически.
- Иконка из оригинальной графики игры и системный экран запуска без стандартной иконки Capacitor. Учитываются системные панели и вырезы через Capacitor SystemBars и CSS safe area.

## Проверки

`npm test` включает Android-контейнер с подставленным native API (Back, pause/resume, отказ транспорта) и игровую логику. `npm run build:android && npm run test:android-web` проверяет все занятия и восстановление частичного пазла в Chromium, блокируя любые внешние запросы. Это не заменяет нативную проверку APK.

Подпись APK проверяется `apksigner verify`, права и версия — `aapt dump permissions` / `aapt dump badging`. `lintDebug` может сообщать предупреждения ресурсов шаблона; успешная сборка не является одобрением RuStore.

Проверено при подготовке: сборка `assembleDebug`, `lintDebug` без ошибок, подпись APK v2, package/версии, отсутствие разрешения `INTERNET`, 34 unit-теста, Android-веб-сценарий, 6 VK-сценариев и 3 затронутых сценария общей игры (звук, пауза SDK, мобильное сохранение).

В версии 0.1.1 игровая логика больше не зависит от `Object.hasOwn` и `Array.prototype.at`, отсутствующих в WebView 89–91. Браузерный сценарий явно отключает оба метода и проверяет запуск шести занятий, восстановление после ответа и частичного пазла. Это проверка отсутствия конкретных API; она не эмулирует целиком старую версию Chromium.

Повторная нативная проверка 21 октября: SDK-образ Android 12/API 31, x86_64, WebView 91.0.4472.114; APK 0.1.1 успешно установлен (`pm install`: Success), MainActivity и плагины создаются, WebView обрабатывает локальный адрес. Виртуализация KVM отсутствует, применяется программная эмуляция. Системный интерфейс Android выдаёт ANR; процесс WebView аварийно завершается, из-за чего функциональные проверки APK не закончены. Проверка простой страницы в штатном WebView Shell также прервана системным ANR; независимое доказательство причины сбоя не получено. Нельзя считать подтверждёнными нативный игровой процесс, кнопку «Назад», офлайн-перезапуск, качество голоса или совместимость всех устройств. Образ Android 15 также не дал стабильного рабочего окружения. Инструкция для дополнительной проверки сохранена в [Android Studio](../../docs/ANDROID-TESTING.md). Владелец сообщил, что не может установить инструменты, и выбрал продолжить подготовку выпуска без дополнительного тестирования.
