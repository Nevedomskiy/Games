# Подготовка версии для VK

## Текущий результат

Подготовлена отдельная сборка HTML5 с официальным VK Bridge 3.0.2 и реакцией на события скрытия/возвращения приложения. Она использует те же задания и сохранения в браузере. Яндекс-сборка и её адаптер не изменены. Прогресс между браузерами/площадками не синхронизируется.

Владелец зарегистрировал аккаунт и создал приложение типа **«Игра»**, жанр **«Головоломки»**, ID **54837649**. Название и описания после обновления страницы сохранились. В разделе «Размещение» указаны HTTPS-поля для мобильного WebView, Web iframe и мобильной версии сайта; приложение пока отключено. В раскрытом меню «Разработка» видны только ключи доступа и хранимые процедуры. Каталог, реклама и выплаты ещё не настроены. Рекламу, разрешения на данные пользователя и платежи игра не запрашивает. Условия допуска детского продукта к рекламе ещё проверяем в кабинете.

## Текущий следующий шаг: GitHub Pages

Для первого тестового запуска выбран GitHub Pages. Сборка отправляется в отдельную ветку gh-pages; это публикация статических файлов, а не регистрация игры в каталоге VK. Основная ветка, код Яндекс-версии и локальные пользовательские файлы сохраняются.

1. После подготовки ветки открыть https://github.com/Nevedomskiy/Games/settings/pages под аккаунтом владельца репозитория.
2. В Build and deployment выбрать Source: Deploy from a branch. Branch: gh-pages, папка: / (root). Нажать Save. Если здесь уже настроен другой сайт, сначала проверить его назначение, чтобы не заменить существующее размещение.
3. После успешной сборки открыть https://nevedomskiy.github.io/Games/ и проверить загрузку игры. В облачной среде запрос к этому домену возвращает proxy 403, поэтому успешный HTTPS-запуск требует отдельной проверки браузером владельца. Не считать сохранение ветки подтверждением работающего сайта.
4. Когда сайт откроется, вернуть его URL с завершающим / в поля размещения VK для мобильного приложения, Web и мобильной версии сайта. Сначала проверить доступный режим разработки и параметры запуска владельцем, затем включать доступность в рамках теста. Реальная работа Bridge в созданном приложении типа «Игра» пока не подтверждена; проверить её после первого запуска во VK.
5. Пройти тест в клиентах VK, затем сверить требования игрового каталога и монетизации, включая аудиторию 2–4 года, самозанятость, страны/статусы получателя, договор и выплаты. Иконка, обложка и тексты есть в docs/store/; размеры и правила медиа сверить с формой VK.

Успешно открывавшийся путь создания: https://dev.vk.ru/ru/admin/create-app. На старой ссылке dev.vk.com/ru/admin/create-app владелец получил «Страница не найдена». Основные настройки: https://dev.vk.ru/ru/admin/app-settings/54837649/info, размещение: https://dev.vk.ru/ru/admin/app-settings/54837649/platform. Секреты, токены и реквизиты в документы и чат не добавлять.

## Команды и файлы

```sh
npm run build:vk
npm run preview:vk
npm test
npm run test:vk
npm run export:vk
npm run publish:pages
```

build:vk сначала строит обычный dist, затем создаёт отдельный dist-vk. В VK-версии kids/platform.js заменён адаптером из platforms/vk/platform.js и добавлен локальный vendor/vk-bridge.js с MIT-лицензией. Обычный дистрибутив Яндекса не получает этот SDK.

Результат: dist-vk/ и artifacts/lapki-i-kraski-vk.zip. export:vk явно обновляет скачиваемый vk-games.zip в корне. Сам ZIP не создаёт приложение и не отправляет его в каталог; официальный статический хостинг использует инструмент развёртывания. Внешних CDN-запросов для Bridge нет.

## Повторная отправка файлов в gh-pages

npm run publish:pages строит dist-vk, формирует отдельное дерево Git из index.html, kids/, vendor/, .nojekyll и публичного build-info.json и отправляет его в gh-pages. Текущая рабочая ветка и индекс Git не переключаются. При повторном запуске сохраняется история gh-pages; force push не используется, конкурентное изменение отклонит отправку. Чужую существующую gh-pages без метки публикации скрипт не заменяет. Source commit в build-info.json позволяет проверить версию.

Перед обновлением выполнить npm run test:vk. Активация сайта в Settings > Pages — отдельный шаг владельца, который скрипт не выполняет. Для проверки тестового адреса VK нужна авторизованная сессия владельца; наличие Pages не подтверждает модерацию или выплаты.

## Альтернативный путь: официальный хостинг VK

Скопировать platforms/vk/vk-hosting-config.example.json в корень как vk-hosting-config.json и заменить app_id: 0 на настоящий числовой ID приложения VK. Оставить static_path: dist-vk и endpoints. app_id: 0 намеренно не позволяет отправку без настройки. Конфигурация в корне игнорируется Git.

Официальный инструмент @vkontakte/vk-miniapps-deploy 1.0.3 уже установлен. Его авторизация требует аккаунта владельца. До подключения учётных данных проверить существующие переменные и привязки по именам/наличию, не выводя значения. Если нужен токен, добавлять его через защищённые настройки среды как MINI_APPS_ACCESS_TOKEN, не через чат и не в Git.

Инструмент после авторизации способен вывести токен в консоль. При работе агента не пересылать сырой вывод авторизации пользователю и не печатать его в инструменты: собирать вывод в закрытый временный файл и показывать только очищенный статус/ссылки. Не копировать токены, OAuth-коды или параметры подписей в документы.

Для первого размещения использовать MINI_APPS_ENVIRONMENT=dev и проверенную сборку; production отправлять после проверки в рамках запроса владельца. Актуальный инструмент обращается к api.vk.ru, oauth.vk.ru и возвращённому API хосту загрузки. Их доступ и авторизацию нужно проверить перед отправкой. Текущий сетевой доступ к ним не подтверждён. Наличие пакета и конфигурации не означает успешное развёртывание.

## Проверка

npm test включает 26 игровых и 6 проверок VK-адаптера: однократная инициализация, паузы, локальный режим, ошибки SDK и тайм-аут. Пять браузерных сценариев проверяют официальный браузерный SDK без внешних запросов, события VK с имитацией транспорта, восстановление после ошибки и мобильный пазл. Отдельно проверяется загрузка модулей и восстановление пазла из подпапки /Games/, как на проектном сайте Pages. Эти проверки не подтверждают настоящий SDK-транспорт и монетизацию внутри аккаунта VK.
